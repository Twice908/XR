## Summary

12 labs were run end to end on the deployed app, one at a time, each with a different student profile, so that the scoring could be checked against what the rules *should* give. Each session was also checked on the instructor dashboard. Bohr was left out at the user's request.

Each score was recomputed by hand from the rules and matched what the API returned. The dashboard showed the same numbers every time. **The arithmetic is right; the problems are in what the rules measure and in labs using different rules.**

### Top issues, in priority order
1. **Biology can be gamed to 100%** (Lab 2). Explanation scoring is keyword-only and watching is not scored. L2-a, L2-b.
2. **Retrieval effort measures UI timing, not thinking.** For identical behaviour Metals/Light/Sound always score 3 and the motion family always 0. R-retrieval.
3. **Sensor CSV never uploads for sessions longer than about 35 s** (64 KB keepalive/beacon limit). Movement stats are always "–". S1.
4. **Security**: unauthenticated xAPI writes for any student, session tokens readable via `/auth/verify`, anonymous sessions for any student id. API section.
5. **The labs do not follow one rule set**: thresholds, blend weights, what "transfer" and "causal coherence" mean, the `complete` flag and the explanation rules all differ. R section.
6. **Random play scores 22–56%** in the motion family. Free coverage point, render-time "decision", 3–4 transfer items. L9-a.
7. **Content errors**: methyl orange orange at pH 7 (L3-a), "following the food" in Respiratory (L2-c), Optics wrong "You predicted" label (L8-a), internal variable names in the Sound summary (L11-b), answer-length give-aways (L2-e, L11-c).
8. **Coach**: deployed is in fallback mode, and the fallback lines are Chemistry-only ("tube", "table") in every lab. L1-c.
9. **Instructor**: no score column, student explanations not readable, raw ids, mislabelled timeline rows, abandoned sessions stuck "In progress". L1-h…k, L4-a.
10. **Sounds**: on by default, up to 76 effects per lab. S3.

### Local vs deployed: what to change (no code change needed for the main cause)
1. **Chrome zoom**: localhost:5173 is at 80%, mmaxr.pages.dev at 100%. In Chrome on mmaxr.pages.dev press Cmd − twice (to 80%), or reset localhost to 100% with Cmd 0. Chrome remembers zoom per site. This is the main reason the deployed client "looks slightly different".
2. The code, CSS, lesson data and 45 models are byte-identical. The other differences are environmental: about 1.5–2.5 s per API call through Funnel (3 s blank first paint), cold CDN loads (one 0.5 MB model took 45 s; Simple Machines took 25–30 s to open), the coach in fallback mode, and an 8 h vs 12 h token lifetime.
3. If the HUD must look the same at any zoom, that needs a code change, which was out of scope for this run.

## Cross-cutting findings

### S1 — Sensor CSV never uploads for real sessions (high)
`mmaxr-webxr-client/src/services/sensorTracker.ts` uploads the whole CSV once, at the end, with `fetch(..., { keepalive: true })` (on leaving the lab) or `navigator.sendBeacon` (on pagehide). Chrome limits both to **64 KB**. One row is about 62 bytes at 30 Hz, so only sessions shorter than about 35 s fit.
Evidence from every deployed session:

| session | lab | duration | sensor |
|---|---|---|---|
| sess_79a6a24e / sess_5298f26f / sess_c3d60834 | chem / chem / resp | 0 s | yes |
| sess_bef7bd9a | physics-sound | 97 s | **no** |
| sess_23518ca7 | matter-properties | 161 s | **no** |
| sess_893adb71 (QA) | biology-101 | 690 s | **no**; request stuck "pending" |

As a result, retrieval effort never gets its movement points, and every "Camera movement / Pointer travel / Head travel" stat shows "–". The upload also only fires when the student leaves the lab, so an instructor who opens the report straight after completion sees no sensor data even when the upload works.

### S2 — Deployed vs local look different
Byte-for-byte checks:
- Built JS/CSS: deployed `index-BNCwq-Ju.css` and `lab-3O8HVw3t.css` match a fresh local `vite build` exactly. The JS differs only in the baked `VITE_*` URLs and the chunk hash.
- Lesson JSON from deployed vs local lesson-loader: same keys and same text for all 13 labs (light and sound differ only by the random plan).
- 45 models: SHA-1 identical between `localhost:3007/assets` and the CDN or Supabase copies.

So the code and assets are the same. The difference comes from the browser:
- **Chrome page zoom is stored per site.** On this Mac `localhost:5173` is at **80%** (innerWidth 1837, DPR 1.6). `mmaxr.pages.dev` is at **100%** (innerWidth 1470, DPR 2). At 80% the HUD text and panels are smaller and the 3D canvas has 25% more CSS pixels, so the camera frames more scene around the HUD. **To make deployed match local, set mmaxr.pages.dev to 80% (Cmd −) or reset localhost to 100%.** No code change is needed for this.
- First paint on deployed is a blank dark screen for about 3 s: the token check (`/users/me`) and `/lessons` each take about 1.5–2.5 s over Funnel. Local is instant.
- On deployed, the camera fly-in to stop 1 is still running when the panel appears. It finished later and matched local.
- On deployed the AI coach is in basic (fallback) mode and shows chemistry nudges (L1-c).
- Deployed token lifetime is 8 h; local is 12 h (`TOKEN_TTL`).

## R — Scoring rules: where the labs differ

Source: `mmaxr-analysis/services/rubric-engine/src/scoring/*.ts`. Every lab is scored on the same six dimensions, 0–3 each. Overall = points ÷ (3 × assessed dimensions). The shared baseline is the chemistry scorer: `predictionDiscipline`, `retrievalEffort`, `metacognition` and `deviceStats` are imported by metals, optics, sound and motion.

### Which scorer each lab uses
| Lab | lessonType → scorer | rubricVersion |
|---|---|---|
| chemistry-101 | chemistry_indicators → `scoreChemistry` | chem-1.0 |
| metals-101 | chemistry_metals → `scoreMetals` | chem-1.0-metals |
| physics-light | physics_optics → `scoreOptics` | chem-1.0-optics |
| physics-sound | physics_waves_sound → `scoreSound` | chem-1.0-sound |
| physics-motion, physics-magnetism, physics-electricity, simple-machines, physics-fundamentals, matter-properties | physics_motion → `scoreMotion` (six labs share one scorer and one `lessonType`) | chem-1.0-motion |
| biology-101, biology-respiratory | → `scoreBiology` | chem-1.0-biology |
| physics-101 (Bohr) | physics_bohr → `scorePhysics` (legacy) | chem-1.0-physics |

All versions are prefixed `chem-1.0`, even for physics and biology. Six physics/chemistry labs report as `lessonType: physics_motion` (Matter is a chemistry lab).

### Dimension by dimension
| Dimension | Shared rule (chem/metals/optics/sound/motion) | Exceptions that break the rule |
|---|---|---|
| Prediction discipline | coverage < 0.5 → 0; else 1 + (accuracy ≥ 0.4) + (median decision ≥ 2 s); same colour every time caps at 1 | **Biology**: not assessed. **Bohr**: `ceil(pred/actions × 3)`, a different formula. The "same colour every time" guard only makes sense for chemistry; in other labs it compares `object.value` (an option id), so it rarely or never fires |
| Retrieval effort | with sensor: time (≥ 3 s → 2, ≥ 1 s → 1) + movement (≥ 0.3 m web / 0.8 m VR → 1); without sensor: ≥ 4 / 2 / 0.7 s → 3 / 2 / 1 | **Biology**: not assessed. **Bohr**: own thresholds (2 s / 0.5 s, 0.5 m / 0.1 m). Because of S1 every real session falls back to "without sensor", so the movement half is never used |
| Revision quality | ratio of wrong-first items later fixed | Thresholds differ in **every** lab: chem/metals `≥1 → 3, ≥0.5 → 2, >0 → 1` minus harmful; optics `≥0.75 / ≥0.5 / >0`; sound `≥0.9 / ≥0.6 / >0`; motion `≥0.75 / ≥0.5 / >0.1`, needs ≥ 3 predictions, and counts an *explanation* (coverage ≥ 0.6) as a "fix". **Bohr**: noticed anomaly → 3 else 0. **Biology**: not assessed. "Nothing to revise → 3" holds everywhere except Bohr |
| Causal coherence | blend → `≥0.9 → 3, ≥0.65 → 2, ≥0.35 → 1` | **Motion family** uses `≥0.8 / ≥0.55 / ≥0.3` on explanation keyword coverage only. **Biology** uses *quiz accuracy* `round(ratio × 3)`, which is recall, not causal coherence. Blend weights differ: chem 0.5/0.25/0.25 (+25% reasoning), metals 0.6/0.4 (+25% reasoning), optics 0.5/0.15/0.35, sound 0.4/0.2/0.4. **Bohr**: not assessed |
| Metacognitive calibration | ≥ 3 rated predictions; mean \|expected(conf) − outcome\| `≤0.35 / ≤0.5 / ≤0.62` | **Biology / Bohr**: not assessed (biology has no confidence ratings at all) |
| Transfer | `round(accuracy × 3)` | **Chemistry and Metals: never assessed** (no transfer task). Optics = first-try accuracy on the convex mirror; Sound = echo_2 + sonar_1 right first time; Motion = "what if?" trials; **Biology = closing-explanation keyword coverage** (not transfer) |
| `complete` | — | chem: server holds the submission; metals: submission; optics/sound: `submitted`; motion: trials ≥ total; biology: final != null; Bohr: noticed an anomaly. The dashboard list uses a **different** flag (`submit_analysis` event present). A Sound session can be `complete:false` in the report and "Completed" in the list, or the reverse |

### R-retrieval — same behaviour, different score in each lab (measured)
In every run below the student locked the prediction and then clicked the action about 1–1.5 s later. Retrieval effort = mean gap between the `predicted` and `acted` events, and each lab stamps `acted` at a different moment:

| Lab | When `acted` is stamped | Measured gap | Retrieval score |
|---|---|---|---|
| Chemistry | dropper "Add indicator" click | 3.0 s | 2 |
| Metals | after the server answers the Run click (the 15.1 s here was my script's own wait — see L5-a) | 15.1 s | 3 |
| Motion family (Matter, Electricity, Fundamentals) | "Run" click; "what if?" items stamp `acted` at the same instant as `predicted` (gap 0) | 0.5–0.6 s | **0 (almost always)** |
| Light | fire / trace click, after a slower lock animation | 4.4 s | 3 |
| Sound | "Run it" after mandatory bench steps (sliders, clap, stopwatch) | 5.9 s | 3 |

This dimension therefore measures UI timing, not retrieval. It is the clearest case of labs not following one scoring rule.

### Prediction-discipline coverage point is free
Chemistry, Metals and all motion-family labs block the action until a prediction is locked, so `coverage` is always 100% and every student gets the first point. Combined with `decisionMs`, which starts when the question renders, a pure guesser still got 2/3 (Lab 4).

### Consequences
1. **Maximum points differ** (chem 15, metals 15, optics/sound/motion 18, biology 6), but overall is a %, so Biology's 2-dimension % sits next to Optics' 6-dimension %.
2. **Biology can reach 100% with keyword lists and no animations watched** (Lab 2). It is the only lab with no process dimensions.
3. **Incomplete sessions get a high %**: only finished dimensions count, so an early quit on easy items looks like mastery (sess_bef7bd9a, Sound, 83%, not complete).
4. **The motion family's causal coherence uses lower thresholds** (0.8 vs 0.9 for a 3) than every other lab.
5. Proposed exceptions to *document* rather than "fix": Biology (no prediction step by design) and Bohr (stub). Everything else should share thresholds.
